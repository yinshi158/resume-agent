# 0003. 校验用举证式（quote 程序验证），不用 embedding 打分

状态：已定稿
日期：2026-09-16

## 背景

embedding 余弦相似度噪声大、阈值不可解释（0.72 和 0.78 差多少？没有
答案），堆关键词的烂简历也能刷高分，且与关键词检查器高度共线。
LLM 直接打分同样漂移（同一份简历跑 100 次分数不稳）。通用原则：
**把校验任务从"打分"改写成"找证据/做映射"——判定任务比评分任务
稳定得多。**

## 决定

1. JD 硬性要求逐条举证：must-have 拆清单，每条让 LLM 在简历里找证据，
   输出"要求 → 证据"映射，找不到即缺口。举证表同时是校验结果和诊断
   报告素材。
2. 证据必须是**原文逐字 quote**，经 normalize 后程序验证为
   canonical_text 子串，拒绝模型转述——牵强配对在 quote 层面会露馅
   或被程序拒收。
3. JD 诊断与校验同构（都输出举证），共用同一套人工标注测试集
   （10–20 份 JD-简历对，M2 开工条件）。
4. embedding 只作经历库变大后的粗排预留；当前量级（几十上百条）
   全量喂，不做检索，不为它漏条目。
5. 真正需要打分的场景（多版本选优）用成对比较，且 A/B 顺序互换各跑
   一次，两次一致才采纳；不做绝对打分。

## 后果

- 正面：每个校验结论可解释、可行动、可程序复验；预检天然偏保守
  （找不到可验证 quote 只能标 gap），与期望的失败不对称方向一致。
- 负面：LLM 调用次数多于一次性打分；quote 校验强依赖 0001 的
  normalize 稳定性。
- 不可逆性：决定 prompt 体系与标注测试集形态，换路线等于重做 M2。
