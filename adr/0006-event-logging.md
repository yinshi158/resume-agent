# 0006. gate_events（含判定快照）+ 版本/投递/结果三表，v1 只记录不分析

状态：已定稿
日期：2026-09-16

## 背景

gate2 的确认/拒绝/编辑行为是免费的人工标注数据，价值高于投递回流：
用户驳回一条被 L2 标红的句子 = 误报信号；用户手改一条未被标红的 =
漏报信号。但只有用户动作、没有当时的校验判定，误报率算不出来。
"投递后是否拿到面试"的结果回流是全开源行业的空白，是长期护城河。

## 决定

1. M3 上线 gate2 时**同步**建 gate_events 表：句子 ID、动作
   （confirm/reject/edit）、编辑前后文本、**当次校验判定快照**、
   时间戳；validate 结果按句子 ID 持久化可关联。
2. v1 同时建"简历版本—投递记录—投递结果"三张表，**只记录不分析**。
3. 分析留待数据积累后做；表结构先行，错过就从第一天开始丢数据。

## 后果

- 正面：误报/漏报率可量化，校验器阈值调优有依据；投递回流数据
  从第一天开始积累。
- 负面：v1 有少量无即时回报的建表成本。
- 不可逆性：事件数据一旦没记，事后无法补录——这是"不做"的不可逆。
